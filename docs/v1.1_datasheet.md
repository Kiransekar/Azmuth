## 1. Device Overview

The Xcew Processor v1.1 is a RISC-V-based AI execution context processor
extending RV32IMC with custom instructions for neural network inference,
accelerated math (EML), and non-volatile memory operations.

### Key Features (v1.1)
- RV32IMC core with 5 custom Xcew instructions
- EML unit: 5-stage pipeline, 128-entry memo cache, 256-entry DAG cache (4-way)
- SNN tile: LIF neurons with TTFS encoding, STDP learning engine
- NVM controller: 64KB ReRAM, wear-leveling, Hamming(32,26) ECC
- Power orchestration: per-tile sleep/wake FSM, retention registers
- Body bias control: digital P/N-well bias, leakage calibration
- Security: constant-time execution, watchdog, SECDED(72,64) ECC, fault monitoring
- Deterministic policy execution with cycle-budget enforcement
- v1.1_mode pin for backward compatibility with v1.0 firmware

## 5. Power Domains and States

### Domain Specifications

| Domain | Voltage | Clock | Switchable | Features |
|--------|---------|-------|------------|----------|
| PD_CORE | 1.2V | 250MHz | No (always-on) | Core, AXI, ROM, SRAM |
| PD_EML | 1.2V | 250MHz | Yes | EML, DAG cache, CT engine |
| PD_SNN | 0.9V | 125MHz | Yes | SNN, TTFS, STDP |
| PD_NVM | 1.8V | 250MHz | Yes | NVM, ReRAM (retention) |
| PD_WAKEUP | 1.2V | 250MHz | No (always-on) | Bias ctrl, fault mon |

### Power State Transition Sequence

```
RUN -> IDLE_DETECT -> SLEEP_PREP -> SLEEP
  ^                                      |
  |______________________________________|
         Wake (IRQ/tile_req/AXI activity)

RUN:    All tiles active, voltage nominal, clocks running
IDLE:   Activity counter reaches zero, timeout starts
SLEEP:  Clocks gated, isolation enabled, retention saved
WAKE:   Power switch enabled, retention restored, clocks ungated
```

### Wake Timing Requirements
- EML wake: 5 cycles setup + 1 cycle hold
- SNN wake: 5 cycles setup + 1 cycle hold
- NVM wake: 8 cycles setup + 2 cycles hold (retention restore)
- Core wake: 5 cycles setup + 1 cycle hold

## 7. Calibration Flow

### Body Bias Controller Calibration
1. Write BIAS_CODE=0x80 (mid-scale) to bias_ctrl CSR
2. Set CAL_EN=1 in bias_ctrl CSR
3. Wait for LEAKAGE_RDY=1 (scan complete)
4. Read optimized BIAS_CODE from bias_ctrl CSR
5. Apply code to pb_bias_out/nb_bias_out

### TTFS Window Tuning
1. Set TTFS_EN=1 in snn_ctrl_ext CSR
2. Configure T_WINDOW (0-7 maps to 10-2000 cycles)
3. Set REFRACTORY period (0-7)
4. Inject test stimulus, measure spike timing vs golden model
5. Adjust T_WINDOW to minimize energy while maintaining accuracy

### DAG Cache Policy
1. Set DAG_MODE=1 in eml_dag_ctl CSR
2. Configure CACHE_POLICY bits for replacement strategy
3. Monitor cache hit rate via debug status
4. Target: >20% hit rate (2x+ reuse)

## 8. Security Features

### Constant-Time Execution
- All EML operations execute in fixed cycle count
- Padding cycles added to equalize operation timing
- Branch-cut detection stalls pipeline on data-dependent branches
- Enabled via sec_ctrl.CONST_TIME_EN

### Fault Monitoring
- Watchdog timer: configurable timeout, auto-reset on tile activity
- ECC: SECDED(72,64) for all memory arrays
- Error codes: watchdog, single-bit ECC, double-bit ECC, soft errors, CSR violations
- Pipeline halt on critical fault with error code latch

### Deterministic Policy Execution
- Fixed-cycle arithmetic prevents timing side channels
- Cycle budget enforcement with timeout IRQ
- Configurable max cycles via pol_sec CSR
